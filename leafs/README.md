# Merkle leaf files

Committed merkle-leaf JSON for each vault/strategist — the ordered `leafs` array plus
the precomputed `MerkleTree` and its `ManageRoot`. This is canonical, version-controlled
content, **not** a build artifact: it stays committed.

## Why the files are stored canonically

They're generated by forge's `vm.serialize*` (`MerkleTreeHelper._generateLeafs`), which
emits JSON **object keys in an unstable order**. Left as-is, every regeneration rewrites
the whole file, so a single change — or any `dev`↔`main` sync — shows a ~200k-line diff
that is ~99% key-order churn (only a few thousand lines are ever real). To keep diffs
proportional to actual changes, committed leaf files are kept in a **canonical form**:
object keys sorted, 4-space indent, trailing newline.

This is a serialization convention only — it is **content-preserving**:

- JSON object key order is meaningless, so sorting keys changes nothing semantically.
- The merkle-ordered `leafs` **array is never reordered** — only object *keys* are sorted.
  So `ManageRoot` and every `MerkleTree` layer are byte-identical before/after.
- (Reordering the `leafs` array *would* change the root and invalidate on-chain proofs,
  which is exactly why arrays are left untouched.)

## Regenerating leaves

After running the forge script that (re)generates a leaf file:

1. **Normalize:** `python3 scripts/normalize_leaves.py` (rewrites all leaf files
   canonically; or pass specific paths to limit scope).
2. **Commit** the result.

Two layers keep this from slipping — you shouldn't have to think about step 1:

- **Pre-commit hook** — `.githooks/pre-commit` auto-normalizes *staged* leaf files and
  re-stages them. Enable once per clone: `git config core.hooksPath .githooks`
  (or run `scripts/install-git-hooks.sh`).
- **CI check** — the `leaf-canonical` workflow fails a PR if any committed leaf file
  isn't canonical, and prints the fix command. This is the non-optional backstop for
  anyone who hasn't enabled the hook.

The two empty `plume/Royco*` placeholder files are intentionally left as-is (skipped by
the normalizer).
