On-chain filled-amount sources (research notes)
-----------------------------------------------
**Common pattern:** all three protocols overwrite the fill slot on cancel/invalidate, so
the adapter MUST snapshot the filled amount *before* issuing the on-chain cancel.

CoW (cleanest)
  Contract:  GPv2Settlement @ 0x9008D19f58AAbD9eD0D60971565AA8510560ab41
  Read:      filledAmount(bytes orderUid) -> uint256
  Units:     sell-token units (sell orders) — our adapter only allows sell orders
  Semantics: monotonic accumulator, capped at order.sellAmount
  Gotcha:    invalidateOrder(uid) sets slot to type(uint256).max. Read BEFORE invalidate.
  Unfilled:  order.sellAmount - filledAmount(uid)

1inch v4 (most work — adapter today blocks partials)
  Contract:  OrderMixin (in AggregationRouterV6 @ 0x111111125421cA6dc452d289314280a0f8842A65,
             or standalone LOP v4 @ 0x119c71D3BbAC22029622cbaEc24854d3D32D2828)
  Reads:     rawRemainingInvalidatorForOrder(maker, orderHash) -> uint256  (preferred — never reverts)
             remainingInvalidatorForOrder(maker, orderHash)    -> uint256  (reverts on untouched)
  Units:     remaining maker amount (maker-asset units)
  Sentinels: raw == 0           -> untouched, unfilled = full makingAmount
             raw == uint256.max -> fully filled OR cancelled (indistinguishable)
             else               -> unfilled = remainingInvalidatorForOrder(...)
  Blocker:   our adapter forces _NO_PARTIAL_FILLS_FLAG (OneInchAdapter.sol:282), which routes
             through BitInvalidator and never touches _remainingInvalidator. Must drop that
             flag and route isFilled / filledAmount through remainingInvalidatorForOrder.
  Gotcha:    snapshot raw BEFORE cancelOrder (cancel writes uint256.max).

OpenOcean (1inch LOP v2 fork — same shape as 1inch with offset-by-1 encoding)
  Contract:  LimitOrderProtocol @ 0xcC8d695603ce0b43D352891892FcC716c6a7C9f4
             (NOTE: 0x6672... in any existing config is wrong — empty bytecode. Check
              the deploy script and any adapter constructor wiring.)
  Reads:     remainingRaw(bytes32 orderHash) -> uint256  (preferred — never reverts)
             remaining(bytes32 orderHash)    -> uint256  (reverts "LOP: Unknown order")
  Encoding:  _remaining[hash] stores `unfilled + 1` (sentinel scheme):
             raw == 0 -> untouched, unfilled = full makingAmount
             raw == 1 -> fully filled OR cancelled (indistinguishable)
             else     -> unfilled = raw - 1
  Gotcha:    same as 1inch — snapshot raw BEFORE cancelOrder (cancel writes 1).
